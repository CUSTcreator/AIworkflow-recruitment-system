# 同步命令运行时与错误合同

本文约束所有由用户 HTTP 请求直接触发的业务写操作。它与异步 Workflow 运行时互补，不能互相替代。

```text
Router → CommandRunner → 领域 Service / 状态机 → 数据库
                    └→ 成功：审计 + 幂等账本 + commit
                    └→ 失败：rollback + 补偿 + 技术日志 + HTTP 错误 DTO

Worker → StepRunner → ExternalActivity → WorkflowStepCheckpoint
```

## 不变量

1. Router 只做 HTTP 参数适配，不得自行提交事务。
2. 领域 Service 只修改当前 Session；同步 HTTP 写操作只由 `CommandRunner` 提交。
3. Workflow 的每个最小可恢复 Step 只由 `StepRunner` 提交；不得套入 `CommandRunner`。
4. 命令回滚表示“本次用户命令未保存”，不得把业务对象改为异步流程的 `failed` 状态。
5. 业务审计只记录成功业务结果；回滚写技术日志，不伪造成功审计。

## 命令身份

| 模式 | 适用范围 | 约束 |
|---|---|---|
| `authenticated` | 普通业务写命令 | 必须有当前 `User` 并完成授权 |
| `anonymous_authentication` | 仅登录 | 仅 `system` 资源、不可幂等、不可写常规业务审计 |

## 错误合同

所有 HTTP 错误返回 `code`、`message`、`retryable`、`action`、`requestId`、`context`。前端不展示 Python 栈、SQL 文本、令牌或简历内容。

| 错误码 | 语义 | 前端动作 |
|---|---|---|
| `command_validation_failed` | 参数或幂等键不合法 | 修改后重试 |
| `command_rejected` | 权限或业务状态不允许 | 展示原因 |
| `command_conflict` | 并发修改或旧视图 | 刷新 |
| `command_transient_failed` | 短暂连接、死锁或超时 | 重试 |
| `command_persistence_failed` | 数据库约束或契约错误 | 联系管理员 |
| `command_internal_failed` | 未预期程序错误 | 联系管理员 |

## 幂等键

前端所有 `POST/PUT/PATCH/DELETE` 自动传递 `Idempotency-Key`。旧客户端未传时，命令运行时通过统一 `compatibility_key()` 生成长度受限的稳定摘要；任何 Router 不得自行持久化或定义字段上限。
